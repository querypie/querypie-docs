# Cloud Providers

### Overview

QueryPieでは、サーバー登録および管理のためのCloud Providerとの連携をサポートします。
Cloud Provider内のリソースを同期し、QueryPieで管理するサーバーに登録し、ユーザーおよびグループに同期してきたサーバーに対するアクセス権限を付与し、ポリシーを設定できます。

### Cloud Provider照会

1. Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providersメニューに移動します。
2. テーブル左上の検索欄を通じて、クラウドプロバイダー名で検索できます。
3. テーブル右上の更新ボタンを通じて、Cloud Providerリストを最新化できます。
4. テーブルでは以下のカラム情報を提供します：
    1.  **Name**: クラウドプロバイダー名
    2.  **Cloud Provider**: 接続プラットフォーム
    3.  **Region**: プラットフォームリージョン
    4.  **Replication Frequency**: 同期周期設定
    5.  **Created At**: クラウドプロバイダー初回作成日時
    6.  **Updated At**: クラウドプロバイダー最終修正日時
5. 各行をクリックすると、クラウドプロバイダーの詳細情報を確認できます。


### Cloud Provider作成

1. Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providersメニューに移動します。
2. 右上の`+ Create Provider`ボタンをクリックします。
3. 以下のガイドを参考にしてクラウドプロバイダーを作成します：
    1. [AWSからサーバーリソース同期](cloud-providers/synchronizing-server-resources-from-aws)
    2. [Azureからサーバーリソース同期](cloud-providers/synchronizing-server-resources-from-azure)
    3. [GCPからサーバーリソース同期](cloud-providers/synchronizing-server-resources-from-gcp)


### Cloud Provider削除

<figure data-layout="center" data-align="center">
<img src="/administrator-manual/servers/connection-management/cloud-providers/image-20240902-044732.png" alt="image-20240902-044732.png" width="505" />

1. Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providersメニューに移動します。
2. テーブル内の削除対象クラウドプロバイダー左側のチェックボックスをチェックします。
3. テーブルカラムラインに表示された`Delete`ボタンをクリックします。
4. ポップアップが表示されたら`Delete`ボタンをクリックして削除を進行します。

<Callout type="important">
Cloud Provider削除時、該当クラウドプロバイダーを通じて同期してきたすべてのリソースが一緒に一括削除されるため、ご注意ください。
</Callout>


### Credential を変更した場合、設定を保存する前に Dry Run を実行する

Credential を変更した後、保存していない状態でも、変更内容で Dry Run を実行して認証と同期対象を事前に確認できます。

従来の Dry Run は保存済みの Cloud Provider 情報を基準に実行されていました。
現在は画面に入力された Credential と Search Filter をそのまま使用するため、保存前に変更内容を検証できます。

<Callout type="info">
本機能は **11.5.9、11.6.7** からサポートされます。
</Callout>

#### Dry Run の検証範囲

Dry Run は次の項目を確認します。

* 入力した Credential でクラウドプラットフォームの認証が可能か
* Search Filter の条件に一致するリソースが照会されるか
* 同期対象リソースの一覧と件数

Dry Run は実際の同期を実行しないため、Cloud Provider、サーバーリソース、アクセス制御設定は変更されません。

#### 保存前に Dry Run を実行する

1. `Admin > Servers > Connection Management > Cloud Providers` メニューに移動します。
2. 対象の Cloud Provider をクリックして詳細画面に移動します。
3. Credential または Search Filter を変更します。
4. 右上の `Dry Run` ボタンをクリックします。
5. ワンタイム入力が必要な Credential 方式の場合は、`Insert more information to dry run` ポップアップで Secret 値を入力します。
6. `Dry run` ポップアップで進行状況とログを確認します。

<Callout type="important">
`Name` と `Replication Frequency` の Cron Expression を除く項目が検証対象です。
AWS、GCP、Azure のいずれも同じ方法で Dry Run を実行できます。
</Callout>

#### ワンタイム Credential 入力が必要な場合

Credential 方式によっては、Dry Run 実行時に Secret 値を追加で要求する場合があります。

* **ワンタイム入力が必要** : `Access Key`、`Service Account`、`Client Secret` のように Secret 値を直接入力する方式です。`Save Credential for Synchronization` オプションがオフの場合、Credential は保存されないため、Dry Run 実行時にもう一度 Secret 値の入力を求められます。
* **ワンタイム入力が不要** : `Cross Account Role`、`Instance Profile`、`Profile Credential`、`Vault (GCP)` のように QueryPie 外部ですでに構成された認証情報を使用する方式です。追加入力なしで Dry Run が実行されます。

<Callout type="important">
`Save Credential for Synchronization` オプションをオンにすると Credential が保存されるため、Dry Run 実行時に Secret 値を再入力する必要はありません。
ただし、このオプションをオンにした状態で保存する必要があり、保存するまではワンタイム入力が要求されます。
</Callout>

#### Dry Run 後の保存と同期

1. Dry Run の結果が正常であれば、`Save Changes` ボタンをクリックして Credential と設定を保存します。
2. `Synchronize` ボタンをクリックして実際の同期を実行します。
3. 同期結果を確認します。

<Callout type="important">
Credential を変更した後、保存せずに `Synchronize` をクリックすると `Save credential changes before synchronizing.` の案内が表示され、同期は実行されません。
先に Credential を保存してから同期します。
</Callout>

<Callout type="info">
Cloud Provider の作成画面でも `Dry Run` ボタンを使用できます。
作成画面では、保存前に 入力した値でそのまま Dry Run を実行します。
</Callout>
