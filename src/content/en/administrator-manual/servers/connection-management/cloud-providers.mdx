# Cloud Providers

### Overview

QueryPie supports integration with Cloud Providers for server registration and management.
You can synchronize resources within Cloud Providers, register them as servers managed by QueryPie, and grant access permissions and set policies for users and groups on the synchronized servers.

### Viewing Cloud Providers

1. Navigate to Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providers menu.
2. You can search by cloud provider name using the search box in the top left of the table.
3. You can refresh the Cloud Provider list using the refresh button in the top right of the table.
4. The table provides the following column information:
    1.  **Name**: Cloud provider name
    2.  **Cloud Provider**: Connected platform
    3.  **Region**: Platform region
    4.  **Replication Frequency**: Synchronization cycle setting
    5.  **Created At**: Cloud provider initial creation date and time
    6.  **Updated At**: Cloud provider last modification date and time
5. Click on each row to view cloud provider detailed information.


### Creating Cloud Providers

1. Navigate to Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providers menu.
2. Click the `+ Create Provider` button in the top right.
3. Create a cloud provider by referring to the following guides:
    1. [Synchronizing Server Resources from AWS](cloud-providers/synchronizing-server-resources-from-aws)
    2. [Synchronizing Server Resources from Azure](cloud-providers/synchronizing-server-resources-from-azure)
    3. [Synchronizing Server Resources from GCP](cloud-providers/synchronizing-server-resources-from-gcp)


### Deleting Cloud Providers

<figure data-layout="center" data-align="center">
<img src="/administrator-manual/servers/connection-management/cloud-providers/image-20240902-044732.png" alt="image-20240902-044732.png" width="505" />
</figure>

1. Navigate to Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providers menu.
2. Check the checkbox on the left of the target cloud provider to delete in the table.
3. Click the `Delete` button that appears in the table column line.
4. When a popup appears, click the `Delete` button to proceed with deletion.

<Callout type="important">
Please note that when deleting a Cloud Provider, all resources synchronized through that cloud provider will be bulk deleted together.
</Callout>


### Running Dry Run Before Saving When Credentials Have Changed

Even before saving after changing credentials, you can run Dry Run with the changed values to preview authentication and synchronization targets.

Previously, Dry Run ran based on the saved Cloud Provider information.
Now it uses the credentials and Search Filter currently entered on the screen, so you can validate changes before saving.

<Callout type="info">
This feature is supported from **11.5.9 and 11.6.7**.
</Callout>

#### Dry Run Validation Scope

Dry Run checks the following items.

* Whether the cloud platform can be authenticated with the entered credentials
* Whether resources matching the Search Filter conditions are retrieved
* The list and count of resources to be synchronized

Dry Run does not perform actual synchronization, so Cloud Providers, server resources, and access control settings are not changed.

#### Running Dry Run Before Saving

1. Navigate to `Admin > Servers > Connection Management > Cloud Providers`.
2. Click the target Cloud Provider to open its detail screen.
3. Change the credential or Search Filter.
4. Click the `Dry Run` button in the upper right corner.
5. If the credential method requires one-time input, enter the secret value in the `Insert more information to dry run` popup.
6. Check the progress and logs in the `Dry run` popup.

<Callout type="important">
All items except `Name` and the Cron Expression of `Replication Frequency` are subject to validation.
Dry Run works the same way for AWS, GCP, and Azure.
</Callout>

#### When One-Time Credential Input Is Required

Depending on the credential method, Dry Run may request the secret value again.

* **One-time input required**: Methods that directly enter a secret value, such as `Access Key`, `Service Account`, and `Client Secret`. If the `Save Credential for Synchronization` option is off, the credential is not saved, so Dry Run asks for the secret value once more.
* **One-time input not required**: Methods that use authentication information already configured outside QueryPie, such as `Cross Account Role`, `Instance Profile`, `Profile Credential`, and `Vault (GCP)`. Dry Run runs without additional input.

<Callout type="important">
If you turn on the `Save Credential for Synchronization` option, the credential is saved, so you do not need to re-enter the secret value when running Dry Run.
However, you must save with this option enabled; until then, one-time input is requested.
</Callout>

#### Saving and Synchronizing After Dry Run

1. If the Dry Run result is normal, click the `Save Changes` button to save the credential and settings.
2. Click the `Synchronize` button to run the actual synchronization.
3. Check the synchronization result.

<Callout type="important">
If you click `Synchronize` without saving after changing credentials, the message `Save credential changes before synchronizing.` appears and synchronization does not run.
Save the credential first, then synchronize.
</Callout>

<Callout type="info">
You can also use the `Dry Run` button on the Cloud Provider creation screen.
On the creation screen, Dry Run runs immediately with the values entered before saving.
</Callout>
