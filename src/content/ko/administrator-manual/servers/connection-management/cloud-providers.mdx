# Cloud Providers

### Overview

QueryPie에서는 서버 등록 및 관리를 위한 Cloud Provider와의 연동을 지원합니다.
Cloud Provider 내의 리소스를 동기화하여 QueryPie에서 관리하는 서버로 등록하고, 사용자 및 그룹에 동기화해 온 서버에 대한 접근 권한을 부여하고 정책을 설정할 수 있습니다.

### Cloud Provider 조회하기

1. Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providers 메뉴로 이동합니다.
2. 테이블 좌측 상단의 검색란을 통해 클라우드 프로바이더명을 조건으로 검색할 수 있습니다.
3. 테이블 우측 상단의 새로고침 버튼을 통해 Cloud Provider 목록을 최신화할 수 있습니다.
4. 테이블에서 이하의 컬럼 정보를 제공합니다:
    1. **Name**: 클라우드 프로바이더명
    2. **Cloud Provider**: 연결 플랫폼
    3. **Region**: 플랫폼 리전
    4. **Replication Frequency**: 동기화 주기 설정
    5. **Created At**: 클라우드 프로바이더 최초 생성일시
    6. **Updated At**: 클라우드 프로바이더 마지막 수정일시
5. 각 행을 클릭하면 클라우드 프로바이더 세부 정보를 조회할 수 있습니다.


### Cloud Provider 생성하기

1. Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providers 메뉴로 이동합니다.
2. 우측 상단의 `+ Create Provider` 버튼을 클릭합니다.
3. 이하의 가이드를 참고하여 클라우드 프로바이더를 생성합니다:
    1. [AWS에서 서버 리소스 동기화](cloud-providers/synchronizing-server-resources-from-aws)
    2. [Azure에서 서버 리소스 동기화](cloud-providers/synchronizing-server-resources-from-azure)
    3. [GCP에서 서버 리소스 동기화](cloud-providers/synchronizing-server-resources-from-gcp)

1. Administrator &gt; Servers &gt; Connection Management &gt; Cloud Providers 메뉴로 이동합니다.
2. 테이블 내 삭제할 대상 클라우드 프로바이더 좌측의 체크 박스를 체크합니다.
3. 테이블 컬럼 라인에 나타난 `Delete` 버튼을 클릭합니다.
4. 팝업이 나타나면 `Delete` 버튼을 클릭해 삭제합니다.

<Callout type="important">
Cloud Provider 삭제 시 해당 클라우드 프로바이더를 통해 동기화해 온 모든 리소스가 함께 일괄 삭제되니 이 점 유의하시기 바랍니다.
</Callout>


### Credential을 변경한 경우 설정을 저장 하기 전 Dry Run 실행하기

Credential을 변경한 뒤 저장하지 않은 상태에서도, 변경 내용으로 Dry Run을 실행해 인증과 동기화 대상을 미리 확인할 수 있습니다.

기존 Dry Run은 저장된 Cloud Provider 정보를 기준으로 실행되었습니다.
이제는 현재 화면에 입력된 Credential과 Search Filter를 그대로 사용하므로, 저장 전에 변경 내용을 검증할 수 있습니다.

<Callout type="info">
본 기능은 **11.5.9, 11.6.7** 부터 지원됩니다.
</Callout>

#### Dry Run 검증 범위

Dry Run은 다음 항목을 확인합니다.

* 입력한 Credential로 클라우드 플랫폼 인증이 가능한지
* Search Filter 조건에 맞는 리소스가 조회되는지
* 동기화 대상 리소스의 목록과 개수

Dry Run은 실제 동기화를 수행하지 않으므로 Cloud Provider, 서버 리소스, 접근 제어 설정이 변경되지 않습니다.

#### 저장 전 Dry Run 실행하기

1. `Admin > Servers > Connection Management > Cloud Providers` 메뉴로 이동합니다.
2. 대상 Cloud Provider를 클릭하여 상세 화면으로 이동합니다.
3. Credential 또는 Search Filter를 변경합니다.
4. 우측 상단의 `Dry Run` 버튼을 클릭합니다.
5. 일회성 입력이 필요한 Credential 방식이면 `Insert more information to dry run` 팝업에서 Secret 값을 입력합니다.
6. `Dry run` 팝업에서 진행률과 로그를 확인합니다.

<Callout type="important">
`Name`과 `Replication Frequency`의 Cron Expression을 제외한 항목이 검증 대상입니다.
AWS, GCP, Azure 모두 동일한 방식으로 Dry Run을 실행할 수 있습니다.
</Callout>

#### 일회성 Credential 입력이 필요한 경우

Credential 방식에 따라 Dry Run 실행 시 Secret 값을 추가로 요청하는 경우가 있습니다.

* **일회성 입력 필요** : `Access Key`, `Service Account`, `Client Secret`처럼 Secret 값을 직접 입력하는 방식입니다. `Save Credential for Synchronization` 옵션이 꺼져 있으면 Credential이 저장되지 않으므로, Dry Run 실행 시 Secret 값을 한 번 더 입력하도록 요청합니다.
* **일회성 입력 불필요** : `Cross Account Role`, `Instance Profile`, `Profile Credential`, `Vault (GCP)`처럼 QueryPie 외부에 이미 구성된 인증 정보를 사용하는 방식입니다. 별도 입력 없이 Dry Run이 실행됩니다.

<Callout type="important">
`Save Credential for Synchronization` 옵션을 켜면 Credential이 저장되므로 Dry Run 실행 시 Secret 값을 다시 입력하지 않아도 됩니다.
다만 이 옵션을 켠 상태로 저장해야 하며, 저장 전까지는 일회성 입력을 요청합니다.
</Callout>

#### Dry Run 후 저장 및 동기화하기

1. Dry Run 결과가 정상이면 `Save Changes` 버튼을 클릭하여 Credential과 설정을 저장합니다.
2. `Synchronize` 버튼을 클릭하여 실제 동기화를 실행합니다.
3. 동기화 결과를 확인합니다.

<Callout type="important">
Credential을 변경한 뒤 저장하지 않은 상태에서 `Synchronize`를 클릭하면 `Save credential changes before synchronizing.` 안내가 표시되고 동기화가 실행되지 않습니다.
먼저 Credential을 저장한 뒤 동기화합니다.
</Callout>

<Callout type="info">
Cloud Provider 생성 화면에서도 `Dry Run` 버튼을 사용할 수 있습니다.
생성 화면에서는 저장 전 입력한 값으로 바로 Dry Run을 실행합니다.
</Callout>
